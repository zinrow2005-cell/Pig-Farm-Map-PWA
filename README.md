# 豬場查詢系統 V3.3.64

## 本版重點：待審數量與管理員案件清單一致

- 正式豬場的修改建議來自 Firestore `suggestions`。
- 新增豬場申請來自 Firestore `farmSubmissions`。
- 管理員以兩個**獨立的 pending 即時監聽**計算待審總數，不再只算前一種案件，也不受最近 50 筆歷史清單截斷影響。
- 清單合併兩個來源，以來源與文件 ID 去重；核准及退回後，依雲端監聽結果同步變動。
- 上方新加「待審 N 筆」快捷按鈕，直接打開「共同編輯 → 待審核定」。
- 讀取尚未完成時顯示「待審讀取中」，讀取失敗時顯示「待審數量無法確認」，不再用 0 誤導。

## 部署

1. 先備份目前站點與資料。
2. 解壓並將本 ZIP 網站檔案（index.html、assets、data、icons、sw.js 等）完整上傳 GitHub Pages。
3. 確認左上版本 V3.3.64；重新開啟 PWA 讓新版快取生效。
4. 以管理員登入，比對待審快捷按鈕與「待審核定」案件數。
5. 核准一筆測試案件，確認待審數量下降，已處理紀錄仍可追查。

**Firebase 規則：** 本次未改寫規則。沿用 V3.3.62 已發布的規則（管理員可以查詢兩種案件集合）。不需要重新匯入 315 筆初始資料。
