# 豬場地圖查核 V3.3.46｜三項核心流程整合版

以 **V3.3.45 完整網站** 為基礎，保留原有雙地圖、F03、管理員、送審、標記、名稱顯示與本機刪除功能。

## 本次新增

1. **同地塊關聯**：使用 F03 地塊 key（人工座標記錄使用原 key）串聯人工查核、待審及正式豬場；管理中心顯示地塊關聯數。已有正式紀錄先搜尋並沿用原 UID。多個正式豬場在同一地塊時不自動合併。
2. **管理中心**：「共同編輯」加入新增／標記、搜尋既有豬場、查看待審快捷入口；既有場址可從清單或地圖修改、核定、刪除。舊版既有的表單、確認及權限不變。從管理中心搜尋但尚未選擇地圖位置時，直接開啟原紀錄編輯，不會當成 (0,0) 定位或建立新筆數。
3. **雲端查核試行**：新增 Firestore `sharedAudits`，登入者完成本機查核後自動嘗試上傳查核摘要；可手動上傳歷史本機查核、讀取雲端查核、匯入目前裝置缺少的地塊查核。管理員可查看所有登入者已上傳的查核，一般使用者僅能查看自己上傳的查核。雲端副本不包含地塊完整輪廓，不會將查核自動核定成正式豬場。已存在的本機地塊紀錄不會被雲端覆寫。

## 操作

- **地圖新增**：標記點 → 選擇地塊 → 填表；可以搜尋既有豬場。管理員直接儲存；一般使用者 Google 登入送審。
- **清單既有資料**：編輯 → 在地圖選擇定位 → 選點 → 確認與儲存。使用原豬場 ID。
- **管理中心**：點「共同編輯」。在管理中心按「搜尋既有豬場」可以開啟正式資料編輯與刪除；「查看待審」可處理案件。
- **跨裝置**：登入相同 Google 帳號，開啟共同編輯 → 讀取雲端查核 → 匯入缺少的查核。原本的本機紀錄可以先按「上傳既有本機查核」。手機與電腦的查核標記不會自動全部互相覆蓋。
- **刪除雲端查核**：讀取後，在自己的雲端查核旁按「刪除我的雲端查核」。這不刪除本機資料或正式豬場；刪除本機標記亦不自動刪除雲端副本。

## 必須同時更新 Firebase 規則

V3.3.46 **需要更新** `firebase/firestore.rules`，原因是新增 `sharedAudits` 和既有豬場建議的地塊關聯欄位。前幾版的規則不夠用。

1. **先備份** 原網站匯出的完整 JSON 及 Firebase Console 目前的 Firestore 規則。不要清空瀏覽器資料。
2. 在 Firebase Console → Firestore Database → Rules 發布本包中的 `firebase/firestore.rules`。若原規則另有自行新增的權限，先人工合併，不可直接覆寫失去其他功能。
3. 解壓縮整個 GitHub Pages 網站包，將根目錄 `index.html`、`assets/`、`data/`、`sw.js` 等全部上傳並覆蓋。
4. 確認 PWA 網頁顯示 **V3.3.46**，再以管理員及一般 Google 登入帳號驗收。
5. **不要重新初始化／補齊原始 315 筆名冊**，也不要刪除舊資料重建。

## 安全界線

- `sharedAudits` 只是人工查核摘要，不是正式豬場或官方核定；不改變上方已匯入總數。
- 匯入雲端查核只補缺少的 key；同一地塊有不同資料時以本機資料為準，需要人工確認。
- 未登入者仍只使用本機查核；已登入但 Firebase 發生錯誤時，本機查核仍在，雲端同步會顯示失敗。
- 因 Firestore 無法在此測試環境連線到你的正式專案，本包**沒有進行正式雲端寫入或 Firestore 規則發布驗收**。請以一筆測試地塊驗證後再大量使用。
